公式中的符号是什么意思？
Np / Ng
预测 / GT 的全部 target 区域数，包含 edit、keep、generated；不含独立 removal 记录。
Ep / Eg
预测 / GT 中 target 区域挂载的全部 source-reference 连接数，一个区域可有多条连接。
M / L
匹配成功的 target 区域对 / source-reference 连接对。
wl

Cl
correspondence_correct：模型判断 source 实体是否确实对应这个 target 实体，取 0 或 1。
Om / Ol
origin_correct：模型判断预测的 edit / keep / generated 来源类型是否符合实际视觉关系，取 0 或 1。
交互示例 / 共享评分规则

Q：把语义判断变成质量分。

Luna low

模型分别判断 precision（正确性）与 recall（覆盖度），再计算调和平均。区域描述、局部指令、全局描述和全局指令各自独立评分。

Q = 2 × p × rp + r严重错误或 p + r = 0 时，Q = 0
本次语义质量分0.600

2 × 0.75 × 0.50 ÷ 1.25 = 0.600

p、r 是模型按 rubric 给出的离散档位。当前流程不先拆成原子事实逐条计数，因此 0.75 不表示严格数出了“75% 的事实正确”。Q 计算则是确定性的。这里的操作仅演示公式，不调用模型，也不是实际 benchmark 结果。

A / TARGET

目标区域质量

同时关注几何位置与描述内容。

01

Target RegionPQ

目标区域的定位精度与覆盖情况

几何 · ↑
2 × Σm∈M IoUtarget(m)Np + Ng

每个成功匹配的区域，按实际 IoU 贡献分数。框的位置越准确，贡献越高；漏掉、多报或重复的区域仍计入分母。

例子预测和 GT 各有 2 个区域，匹配 IoU 为 0.9、0.7：2 × (0.9 + 0.7) / 4 = 0.800
02

Target Desc F1

目标区域描述的视觉事实质量

模型评分 · ↑
2 × Σm∈M Qdesc(m)Np + Ng

对匹配区域的 desc，模型检查对象、数量、文字、颜色、方向和关系。precision 衡量事实正确性，recall 衡量重要可见事实的覆盖度，严重错误令该区域 Q 归零。

Qdesc 使用上方的共享 Q 公式。IoU 负责匹配门槛，进入分子的是语义 Q，不再乘一次 IoU。

例子双方各 2 个区域，Q 分别为 0.6、1：2 × (0.6 + 1) / 4 = 0.800
03

Caption Embedding F1

匹配区域描述的向量语义相似度

Embedding · ↑
2 × Σm∈M clip(cos(vp, vg), 0, 1)Np + Ng

将预测与 GT 的区域 desc 分别编码为向量，比较余弦相似度并裁剪到 [0, 1]。空描述贡献 0，漏检与多报通过分母扣分。

Embedding 的固定配置

模型：sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2
Revision：e8f8c211226b894fcb81acc59f3b34ba3efd5f42
最大 512 tokens；attention-mask mean pooling；L2 归一化。只比较匹配区域的 desc，不编码整个 JSON。向量相似不保证细节事实正确，需结合 Target Desc F1 阅读。

B / SOURCE → TARGET

来源对应与局部编辑

定位、实体对应和编辑指令，是不同的判断。

04

Reference GroundedPQ

两端定位准确，且来源实体对应正确

几何 × 模型 · ↑
2 × Σl∈L wl × ClEp + Egw = min(IoUtarget, IoUsource)

两端 bbox 的较小 IoU 代表定位质量；C 表示 source reference 是否确实指向对应的来源实体。即使框很准，C = 0 时这条连接也贡献 0。

“同一个来源实体”如何判断？

几何匹配完成后，Luna low 接收完整 source / target 图片及文本形式的 bbox、区域描述、编辑信息和 GT 上下文，判断来源框指向的是否是 target 实体真实的来源，而不是背景或另一件相似物体。它输出 correspondence_correct 布尔值和文字证据。

例如杯子变色、移动后仍可对应同一实体；另一只相似杯子不能仅凭外观接近就算正确。这是模型视觉判断，没有独立验证的实例 ID 或单独身份置信度。重复对象、遮挡或大幅变化可能带来歧义。

05

Local Edit Instruction F1

局部区域“如何修改”的指令质量

模型评分 · ↑
2 × Σm∈Medit Qinstruction(m) × OmNpedit + Ngedit

只对预测与 GT 都标为 edit 的匹配区域计入分子。模型评估编辑对象、范围、修改前后状态、方向、属性和保留约束，得到 Qinstruction；O 判断 edit 来源类型是否正确。

例子实际需要“杯子变红并右移”，预测只写“变红”。假设模型给 p = 1、r = 0.5、无严重错误，则 Q ≈ 0.667；方向写反并被判严重错误时 Q = 0。

分母包含双方所有 edit 区域。这个指标不显式乘 source IoU 或 C，不能单独证明来源对应正确。keep、generated 的局部指令与独立 removal 记录不参与。

整条编辑连接各环节同时成立的质量

GT 为 edit 时，J = Qinstruction；GT 为 keep 时，J = O。由于 O 为布尔值，keep 的 O × O = O。任何必要因素为 0，这条连接的贡献就为 0。

未匹配或重复连接仍在分母中。无 reference 的 generated 区域和独立 removal 记录不属于 edge 指标。删除操作的独立评价见新增的 Removal GroundedPQ 设计。该分数不额外乘 Target Desc 的质量分。

全局描述与整体编辑

整段文本独立评分，描述内容与编辑过程分别衡量。

07

Global HLD F1

整张目标图的描述质量

模型评分 · ↑
Qglobal description

直接评价 high_level_description 整段文本。以 target 图片为最终依据，参考 GT 描述，判断场景、对象、数量、文字、颜色、布局和关系是否正确、重要信息是否完整。

对该段文本单独给 p、r 和 critical_error，再套用 Q 公式。它不由局部区域分数平均得出；与其他 scope 的严重错误标记相互独立。

08

Global Instruction F1

整体 source → target 编辑指令质量

模型评分 · ↑
Qglobal instruction

直接评价 normalized_edit_instruction。precision 判断所描述的修改是否真实、对象和方向是否正确；recall 判断新增、删除、属性变化、移动及布局调整等重要变化是否覆盖完整。

单独计算全局指令的 Q。模型查看 source / target 和 GT 上下文；原始用户指令及候选模型身份未提供给评分模型。

09

Global HLD 严重错误率

全局目标描述发生严重错误的 case 比例

错误率 · ↓
Σi∈S 1[global_description.critical_error]|S|

每个 case 的全局描述严重错误标记为 true 记 1，否则记 0。在双方都有有效分数的相同 case 集合 S 上取平均。典型严重错误包括关键身份、数量、显著文字错误或重大幻觉。

例子100 个有效配对 cases 中有 8 个被标记：8 / 100 = 0.080。被标记的 case，其 Global HLD F1 同时归零。
10

Global Instruction 严重错误率

全局编辑指令发生严重错误的 case 比例

错误率 · ↓
Σi∈S 1[global_instruction.critical_error]|S|

对全局指令的严重错误标记求平均，越低越好。修改方向写反、编辑对象错误、关键数量或文字错误、否定关系错误及重大虚构修改都可能被标记。

该标记只决定这个 case 的全局指令严重错误率及其 Global Instruction Q，不会自动改变 HLD 的错误标记。

D / REMOVAL

删除操作质量

在 source 中定位被删除的内容，再判断实际删除关系是否成立。

11

Removal GroundedPQ

删除区域的定位质量与实际删除对应正确性

新增设计 · ↑
当前状态：指标设计已补充，评分尚未实现。现有 477-case 结果未计算此项。下方为建议的计算与汇总口径，示例不是实际评分结果。
2 × Σm∈Mremove IoUsource(m) × CmDp + Dg

全局指令可以正确写出“删除杯子”，但结构化 remove 记录仍可能遗漏或框错。这项指标直接评价独立 removal 记录，补充现有 Editing Edge Joint F1 的覆盖范围。

第一步：确定删除项并做 source 匹配

每个 removal 记录中的 source reference 作为一个删除项；同一记录有多个 references 时分别展开。Dp、Dg 为双方全部删除项数量。匹配限于相同 source frame，以 source bbox IoU ≥ 0.50 做 Hungarian 一对一匹配，最大化总 IoU。重复或未匹配的删除项仍计入分母。

删除对象没有对应的 target 区域，因此这里不要求 target bbox，也不使用 target IoU。

第二步：判断是否找对了实际被删除的内容

Cm 为模型的 0/1 判断：预测 source 框是否指向与 GT 删除项对应的对象或组件，且该内容在 target 中确实被删除。对象只是移动、变色或修改后仍然存在时，不应判作删除。模型需要同时查看 source、target 和冻结 GT，输出判断证据。

这仍是模型辅助的视觉判断；裁剪、遮挡和高度相似对象可能造成歧义，不能将 GT 字段相等直接当作删除关系正确。

评价范围：Q_remove 固定为 1，不单独评价局部删除指令

删除操作已经由 removal 项定义，因此将 Qremove 固定为 1，从公式中省略。评分只保留 source bbox IoU 与实际删除对应判断 C；C 仍需要模型结合 source、target 和冻结 GT 作视觉判断。无需计算局部删除指令的 precision、recall 或质量 Q，也不额外乘 edit / keep / generated 类型因子 O。

局部删除指令文本的错误或遗漏，不会被此指标单独惩罚。Global Instruction F1 继续评价全局编辑指令，但不会自动检查每条局部删除指令。结构化删除项缺失、重复、框错或找错对象，仍会通过匹配、分母和 C 扣分。

例子双方各有 1 个删除项：source IoU = 0.8、C = 1，则 2 × 0.8 × 1 / (1 + 1) = 0.800。若 C = 0，该项贡献为 0；若额外多报 1 个删除项，则分数为 2 × 0.8 / (2 + 1) ≈ 0.533。

漏删与误报删除都扣分

GT 有删除、预测遗漏：GT 删除项只进入分母。GT 没有删除、预测却报告删除：多出的预测项只进入分母。重复框同样增加分母，但一对一匹配不会重复加分。

双方均无删除时

单 case 的 Dp + Dg = 0，此项为 N/A，不记成 0 或 1。在下方 micro 汇总中，它对分子和分母均贡献 0。

汇总建议：使用同一 case 集合，按删除项做 micro 统计
Removal GroundedPQmicro = 2 × Σi∈S Σm∈Mremove,i IoUsource(m) × CmΣi∈S (Dp,i + Dg,i)

两组都在相同、固定的 case 集合 S 上分别累计分子与分母，再计算比值。没有 GT 删除但有预测删除的 case 必须保留；不使用“双方 per-case 指标都非空”的交集过滤，否则会漏掉一组误报删除、另一组正确不删除的惩罚。

这种 micro 口径按删除项汇总，与前 10 项的 case 级宏平均不同。若整个集合的分母为 0，该组分数为 N/A；某组缺少必要的模型判断时，标记结果未完成，不将失败默认为 0，也不声称得到了完整比较。

建议随分数一起展示：固定 case 数、GT 删除项数、预测删除项数、匹配项数、未匹配预测／GT 项数，以及 GT 无删除 cases 上的误报项数。这样可区分删除能力不足、定位不准和过度报告删除。

每一行，使用同一组有效配对 cases。

宏平均 = Σi∈S metric(casei)|S|

先计算，再平均

每个 case 权重相同。先把各 case 的 p、r 转为 Q，再求平均；不把所有区域合在一起计算，也不先平均 p、r。

每项有自己的配对 N

两组均有非空分数才进入该行。均值与 delta 使用相同 cases。几何和 embedding 不依赖 judge 成功，保留完整静态覆盖。

零分与 N/A 有区别

双方 target 区域数都为零时，前三项为 0。双方没有 reference 时，edge 指标为 N/A；双方没有 edit 区域时，Local Edit Instruction F1 为 N/A。

失败记录如何处理

原生无效预测按空预测计分，适用质量分为 0。API 或评分校验失败保留为缺失语义分，不伪装成零分。原生失败的 critical_error 标记为 false，所以严重错误率不等于总失败率。

本节宏平均规则适用于前 10 项现有指标；新增 Removal GroundedPQ 建议使用上节的删除项 micro 口径，以纳入误报删除。GT 是冻结的模型辅助参考（Astra medium），不是人工认证真值。477 cases 来自原始 500-case 请求中已验证的 GT 子集。当前评分报告仍输出已实现的十项指标；第 11 项尚未产生实际评分。
